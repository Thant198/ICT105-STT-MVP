## 3. Problem Background

University students often receive announcements, events, and project information from multiple platforms such as social media, email, and chat groups. Important information is easily missed because it is scattered across different communication channels. CampusLife Hub provides one centralized platform where students can easily access important campus information.

---

## 4. Target Users

The primary users are university students who need quick access to campus announcements, events, and project information.

The secondary users are administrators who manage campus announcements, events, and project updates.

---

## 5. Evidence Summary

The project idea was validated through interviews, discussions, and user testing conducted during previous labs.

User testing showed that students preferred having all campus information available in one place. Testers also suggested improving navigation labels, search clarity, and dashboard descriptions before the final release.

---

## 6. Final Prototype Overview

CampusLife Hub is a web-based prototype that provides a centralized platform for campus communication.

Main features include:

- Landing Page
- Login
- Homepage
- Announcements
- Events
- Projects
- Search
- Dashboard
- Admin Page

The prototype demonstrates the complete user flow from the landing page to the administration page.

## 9. Validation and User Testing Results

Five university students tested the prototype.

Most users completed all main tasks successfully, including:

- Login
- Navigation
- Viewing announcements
- Viewing events
- Viewing projects
- Searching information
- Viewing dashboard
- Opening the admin page

The main feedback focused on improving navigation labels, dashboard descriptions, and search usability.

## 11. Business Value and Venture Direction

CampusLife Hub creates value by reducing information fragmentation across campus.

Students receive announcements, events, and project information through one platform, while administrators manage content more efficiently.

Future development could include:

- Mobile application
- Real-time notifications
- Student authentication
- Integration with university information systems

---

## 12. Limitations and Future Improvements

Current limitations include:

- Prototype only (no backend database)
- Simulated data
- Limited search functionality
- No real user authentication
- No notification system

Future improvements include:

- Database integration
- User authentication
- Real-time notifications
- Mobile responsiveness
- Advanced search and filtering
- Analytics dashboard
- Cloud deployment
